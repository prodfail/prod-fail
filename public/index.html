>How I actually work

Verification-gated AI development

AI writes a lot of my code. It is never the thing that decides the code is correct. Every project runs the same four-stage loop. Stages three and four are machine-enforced. If they fail, nothing ships.

01 / 04

Frame the constraint first

Before any code is generated, the non-negotiable property is written down: this module is read-only; risk attaches to the engagement, not the vendor; the workflow must match the written policy exactly. The constraint is the spec, and it is what the AI is held to.

artifacts
  • M365IR: read-only investigation split from containment at the module boundary
  • Vendor risk: schema built so one vendor can hold many engagements across many orgs
  • Policy alignment treated as a hard requirement, because divergence is a self-inflicted audit finding

02 / 04

Generate against the spec

The model does the volume work: module scaffolding, pagination math, OData filter construction, question-pack authoring. Fast, broad, and assumed wrong until proven otherwise.

artifacts
  • Search-UALComplete: paged UAL retrieval that avoids silent truncation at ~50k records
  • Message trace: automatic 10-day window slicing under the 90-day retention ceiling
  • Answer library: ~45 questions across 7 governance domains, three maturity tiers each

03 / 04

Verify mechanically

The gate. Offline test suites and dependency-free validators assert the properties actually hold, exit non-zero when they do not, and run on every push. No human reads a diff and declares it fine.

artifacts
  • Pester suite asserts the read-only guarantee, so a stray Set-/Remove- cmdlet fails CI
  • validate_schema.py executes the schema and asserts append-only guarantees fire
  • validate_packs.py checks referential integrity and the every-question-ships-guidance contract
  • Date-window slicing and confirmation-gate enforcement covered by tests, no tenant required

04 / 04

Leave an evidence trail

Anything consequential records what happened, in a form someone else can audit later. This is the same discipline whether the actor is a person, a script, or a model.

artifacts
  • Every case folder: timestamped CSV + JSON exports, SHA256 hashes, chain-of-custody manifest
  • AI is opt-in per document; every send is written to an ai_disclosure_log with source excerpt and page
  • Model output stays "suggested" until a human accepts it, never auto-applied
  • Containment requires a typed random token; two-phase purge with mandatory review, no hard delete
Say what you do, do what you say.

The reason the checks are automated is that a control which depends on remembering to run it is not a control. If the tooling and the written policy disagree, the tooling is wrong, and the test suite should be the thing that tells you, not the auditor.

M365IR

PowerShell module · DFIR

Archived

A tested incident-response module for Microsoft 365, built for the analyst working a breach at 2am, where a missed page of audit log is a missed attacker.

Vendor Risk Platform

Desktop application · GRC

Private

A local-first vendor risk management platform. No server, no client login, no data leaving the machine. Reports are handed over as files.

  • Every question ships with intent, evidence guidance, control mappings and pre-written remediation text, enforced by a pack validator
  • Question content authored in-house from public-domain NIST material to stay clear of SIG and CAIQ redistribution terms
  • Risk attaches to the engagement rather than the vendor, so one vendor can span several orgs at different tiers
  • Tiering is configuration data, not code, so it maps onto written policy without a refactor
  • AI assistance is opt-in per document, logged with source excerpt and page, and stays suggested until a human accepts
  • Append-only schema with override reasons, asserted by an executable schema validator

Network Edge Hardening

Infrastructure · Blue team

Private

Rebuilt a production OPNsense edge around inline prevention and measured resource honesty, removing a tool that was detecting without blocking.

  • Suricata running inline IPS via netmap on the LAN segment, inspecting both directions
  • CrowdSec deployed with automatic acquisition and bouncer registration
  • Removed Maltrail after finding it populated a block table no firewall rule referenced. Detection theater, with four sensors holding ~7GB RSS
  • That removal freed ~2.2GB RAM and dropped swap usage from 27% to 6%
  • SSH hardened to key-only auth, with the single-admin blast radius mapped before any change
  • Policy-routed VPN egress with a kill-switch block rule beneath it, and DoT blocked to prevent resolution bypass
